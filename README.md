# bandori-ournotes-dub-script

《BanG Dream!》二创辅助工具。把**中文台词**落成「这个角色会这么说」的**日文配音台本**，
并给出配音用的**名字注音稿**。

覆盖 MyGO!!!!!、Ave Mujica、梦限大MewType、millsage、一家Dumb Rock!（家团）五团 25 人 + 团外 1 人（沢海奏多）。

安装后，可向它提出以下问题：

- 祥子这句中文，日文该用 `わたくし` 还是 `私`？
- 爱音叫灯是 `ともりん` 还是 `燈ちゃん`？——这一场是早期还是后期？
- 若麦会怎么叫海铃？她要叫「小海」的话，日文是什么？
- 这句台词给海铃，她会不会转敬体？
- 把这段中文台词出成日文配音稿，再给一份 TTS 能正确读音的注音稿。

## 用途

日语是黏着语，**人格长在语法里**，并且有敬语体系。现代汉语作为分析语基本没有这些语法位置，所以中→日的难点不是词汇，
而是「中文没写的，日语必须补出来；补错了，人物就走形」。

| 日语必须补的位置 | 现代汉语的实际情况 |
|---|---|
| **自称**（私／僕／あたし／うち／わたくし） | 变化较少，强行使用谦敬词可能影响文风 |
| **二人称与呼称**（さん／ちゃん／呼び捨て／あだ名） | 变化较少，强行使用谦敬词可能影响文风 |
| **语尾终助词**（わ／のよ／じゃん／っしょ） | 「吧／呢／啊」粒度较粗 |
| **敬体 vs 常体**（です・ます vs だ） | 动词不变化，实词替换难度较大 |
| **授受补助**（〜てくれる／もらう／あげる） | 强行使用谦敬词仍不足以覆盖，且可能影响文风 |

总之，为了在配音过程中还原角色形象，翻译的日语台本必须按人换一套。

*示例*：

| 中文（同一句） | 落成灯 | 落成若麦 |
|---|---|---|
| 「知道了，我去看看」 | `……わかった` | `オッケー、行ってみるわ〜` |


## 作用范围

| 作用范围 | 非作用范围 |
|---|---|
| 中文台词 → 日文台词的**说话方式** | 角色的**人设与剧情**（一设或者二设） |
| 自称、呼称、语尾、敬体、授受怎么落 | WebGAL 的**演出与表情建议**（只在与模型对不上时给判据） |
| 谁怎么称呼谁、什么时候换了叫法 | 把**官方中译**当标准答案（它会抹平语体） |
| 配音稿 / TTS 注音稿 | 替用户改中文原文的内容 |

## 输出产物

**一份日文台词稿**（纯日文，不夹注、不给表情与语音提示——夹注会被念进去）：

```
乐奈：バンド、やる？
爱音：え、なにそれ、めっちゃいいじゃん！
灯：……うん
```

**需要时再给一份注音稿**（只改名字写法，台词内容与标点一字不动）：

```
台词稿：祥子：豊川さん、三角さんと八幡さんも呼ぶ？
注音稿：祥子：とがわさん、みすみさんとやはたさんも呼ぶ？
```

说话人标记（`祥子：`）不进 TTS，保留原样，以便于用户复核。

## 给 GPT-SoVITS 的注音

日语 TTS 的前端**靠词典猜汉字读法**，生僻人名必读错：

| 写法 | 词典会给 | 正确 |
|---|---|---|
| 豊川 | とよかわ | **とがわ** |
| 三角 | さんかく | **みすみ** |
| 馬橋 | まばし | **まはし** |
| 梅里 | うめさと | **うめざと** |

技能内含 26 人的**官方读法表**，做法是「只换写法、不换台词」：

```bash
node tools/vtool.mjs read                              # 打对照表（不需要语料包）
node tools/vtool.mjs read --in 台词稿.txt --out 台词稿_注音.txt
```

脚本只改「说话人：」之后的台词，单字名（燈/睦/律/凪/蛍/要/藤）只在左边不是汉字时才换，
所以 `必要`／`法律`／`要点` 不会被误伤。

## 核心：先定「她想表达什么」

**中→日的难点不在词汇层面。** 同一句台词，若她此刻的意图不同，翻译应落成两句不同的话。
每句动笔前按这个顺序自问，**顺序不可颠倒**：

1. **她此刻想要什么？**——想让对方做出什么反应？在试探、在让步、在把话堵死，还是顺口带过？
2. **这个意图在她与对方的关系里，会落成哪种说法？**
3. **最后才是形式落地**：自称、呼称、语尾、敬体、授受如何挂接。

若先做完第 3 步、再回填第 1 步，产物即呈机翻形态：**语义无误，人格缺失。**
判定标准：**一句日语若换由他人说出仍成立，则该句不合格。**

**意图读出两种、或根本读不出时，不应代用户取舍**——在对话中列出候选、说明代价，
**确认可以多轮**：相较反复确认的成本，人物走形的代价更高。
先确认意图，再确认措辞——「用 `〜のよ` 还是 `〜わよ`」在意图未定时无从选择。

由此推出——**禁止以脚本批量产出台本**：工具只做查表、换写法（注音）、体检（只判形式）三件事；
不得调用翻译 API、不得以词典正则完成替换、不得以脚本将整幕一次成稿。
理由是结构性的：自称、呼称、语尾、敬体、授受这五层**在中文原文中没有语法位置**，
只能从「这个人、这一刻、想要什么」推出。

做法是**逐句揣摩**（`01` 第四节）：一句一行，先写「她想要什么」，再定说法、最后落地；
一次只处理一幕（**≤ 30 句**），完成一幕即跑一次 `audit`。详见 `SKILL.md` 的「核心」一节。

## 几点需要留意之处

- **只统计「说出口的称呼」**：日语大量场合直接省略称呼，省略同样正确；表里没有某一对，
  只说明原文没这么叫过，不等于这么叫是错的。
- **低频不等于错**：次数少说明原文里少用，用户要用是他的自由。
- **同一角色跨作品会变**：本技能的数字来自 Our Notes 一部作品，不要套到别的作品上。
- **台上代号是「演出来的那一版」语体**，不是另一个人格：切换到台上时自称、语尾、敬体、句长
  **四层一起换**，只换一个词是最容易读出来的破绽。
  另：若叶睦的 `mortis` 属 DID 人格，**不在本技能范围内**。
- **语言指纹一律取自日文原文**：中文译文会抹平自称、二人称、语尾与敬体，据译文反推语感会有偏差。
- 本技能**不含剧情原文，也不含官方中译**；`07` 里的数字口径可以脱离语料独立阅读。
