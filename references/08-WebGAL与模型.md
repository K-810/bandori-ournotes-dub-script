# 08 · WebGAL 演出（Live2D 模型与表情）

> 给用 WebGAL 做二创的创作者。**先看自己用的是哪套模型**——两套的写法和用法完全不同。
>
> **本技能只做台词翻译，不管演出。** 这一页只解决一件事：模型对不上时，`changeFigure` 该写哪个码。
> **不给动作/表情建议，也不解释码的含义**（不同创作者理解不同，硬定标准反而有害）。
> **使用者没提供语料包时，整页可以跳过。**

## 〇、两句话版本

| 你的情况 | 做法 |
|---|---|
| 模型是 `.model3.json`（新） | 表情用游戏原生 `exp_*`；**用 `vtool model <模型目录>` 列出它实装了哪些**，照抄 |
| 模型是 `model.json`（旧） | **别做映射**；从台词定情绪，自己挑一个名字能读懂的 |
| 有原文包 | 想对齐游戏原始演出时，`vtool exp <集号>` 查该集的 `exp_*` / `mtn_*` |

## 一、一眼分辨：看 `changeFigure` 里的模型文件名

| | **新模型** | **旧模型** |
|---|---|---|
| 文件名 | `xxx.model3.json` | `model.json` |
| 例 | `OurNotes_v101_Live2D_Full/sakiko/live_01_stage/live2d_sakiko_010_live_01.model3.json` | `mygo_avemujica_v5/sakiko/341_casual-2023_rip/model.json` |
| 表情名 | **`exp_*`**（游戏原生码） | 数字／别名（`smile03`、`shame01`、`pui01`、`右转身`…） |
| 动作名 | **`mtn_*`** | `nf01`、`sigh01`、`bye01`、`thinking01`… |
| 与游戏对应情况 | 完全对应 | 老手游素材，与新游戏对应不同 |

**判据一句话**：`changeFigure:` 那一行里出现 `.model3.json` 就是新模型。

## 二、新模型：表情码与游戏一一对应

新模型的表情就是游戏的 `exp_*`，**逐字相同**。所以：

- 写 `changeFigure` 时 `-expression=` 直接填这些码；
- **用 `node vtool.mjs model <模型目录>` 列出该模型实际可用的码**——照抄，不要凭记忆写；
- 有语料包、想对齐游戏原始演出时，用 `node vtool.mjs --pack <语料目录> exp <集号> [角色]` 查该集的原始标注。

**注意**：新模型**只实装了游戏表情里的一部分**（分角色不同）。写码之前先确认该模型有没有这一个。

> 本技能**不解释码的含义**。同一个码在不同语境、不同创作者眼里都不一样，写成对照表反会被当标准答案。

## 三、旧模型：**不要做映射**

旧模型的两条硬事实（务必记住）：

1. **同一编号在不同模型里含义可能完全不同**——`smile03` 在这个模型上是这个意思，在另一个模型上可能不是；
2. **编号本身没有语义**，且各模型的可用表情集合不一样。

所以对旧模型，正确做法是**从文本定情绪，再挑一个你自己看得出意思的名字**：

```
第一步  读这句（原文 + 中文），判断此刻是什么情绪与力度
第二步  在旧模型的表情表里挑一个你认为对得上的（名字通常可读）
第三步  写 changeFigure，-expression= 填这个名字
```

**这也是为什么旧模型用不上「码对照表」**：有意义的是**你对文本的判断**，不是码本身。

### 旧模型的表情清单怎么拿

旧模型（Cubism 2 的 `model.json`）**把表情定义写在文件自身的 `expressions` 数组里**，
不必去找别的文件：

```bash
# 列出该模型的全部表情与动作名
node vtool.mjs model <模型目录>
```

实测一个旧模型（`mygo_avemujica_v5/anon/037_casual-2023_rip`）有 **58 个表情**，
名字本身可读，直接挑：

```
cry01 cry02 · sad01 sad02 sad03 · angry01–04 · serious01 serious02
smile01–04 · shame01 shame02 · kime01 kime02 · kandou01 kandou02
pui01 · sigh01 sigh02 · wink01 · bye01 bye02 · thinking01–03
surprised01 surprised02 · default · idle01 · 另有 T_ 前缀的一整组
```

> 上面只是**名字清单**，不含释义——每个名字在你眼里是什么意思，由你自己定。

> `T_` 前缀的是该模型的另一组同名表情（常见于「带表情的立绘变体」），写之前先试一个看效果。
> **跨模型不要套用**：同一个 `smile03` 在另一个角色/另一套模型上可能不是同一个表情。

### 为什么这里不给「表情 → 情绪」的对照表

**本技能故意不提供旧模型的槽位释义**，理由是它本质上不可标准化：

- 同一个表情在**不同语境**下含义不同（`sigh01` 可以是无奈、也可以是释然）；
- 不同使用者对同一个表情的理解也不同；
- 一旦写成表，就会被当成"标准答案"，反而限制创作者。

所以这里只做两件事：**告诉你有哪些槽位**（`vtool model`）、**把判断权留给创作者**。
使用者可以自行在本地记一张自己的对照表——那才是这份资料真正该有的形态。

## 四、与本技能的关系

- 本技能**只管台词**（中→日语体翻译与自检）。演出属于 WebGAL 侧，只有这一页交集。
- **不给动作/表情建议**：哪个码适合哪句，由创作者自己定。
- **交付的日文台词里不写任何表情提示**——那是 `changeFigure` 的事。

> **没有语料包的使用者：这一页可以整段跳过。** 你只需要知道模型是 `.model3.json` 还是 `model.json`，
> 以及用 `vtool model` 列出模型自己的表情名。
