# 01 · 翻译规程（中 → 日）

> 本文件是主规范。**本技能只做一件事**：把创作者写的中文台词，落成"这个角色会这么说"的日语。
> 输出是**纯台词文本**，不夹注、不给演出建议。

## 一、交付格式：**只出日文台词**

```
乐奈：バンド、やる？
爱音：え、なにそれ、めっちゃいいじゃん！
灯：……うん
```

- **一行一句，`说话人：日语`**。说话人用创作者的写法（中文名或 id 都行）。
- **不给**中文对照、不给注释、不给表情/动作提示、不给语音提示——正文就是台词本身。
- **不保留中文**：创作者手里有原稿，交付物只放日文。
- 需要分场时，场次标记单独一行（`【练习室】`），与剧本习惯一致。

**如此严格的原因**：这是**配音用**的稿子——夹注会被念进去、会被创作者删一遍，也会增加对照成本。
任何"想说的话"都放到对话里说，不要写进稿子。

## 二、判决优先级（冲突时按此顺序）

1. **内容层（中文原文）**：创作者想说什么，不许改。
2. **角色语体档**：自称、二人称、敬体度、高频语尾——整篇一致，不许飘。
3. **场合**：对陌生人、公开场合可以整套升级语体，但**要整句一起换**，不能只换一个词。
4. **日语的自然是最后一位**：宁可日语略硬，不许人物走形。

> 这是本技能与通用翻译最大的分歧点：**通用翻译求"像日语"，这里求"像她"。**

## 三、建角色语体档（六行，先建再译）

对每个出场的角色，先写出这六行，贴在稿子开头（**不进交付物**，只是你自己用）：

```
角色：要乐奈（rana）
① 自称：私（几乎不出现，全篇 3 处）→ 日语里也尽量不出现
② 对主要对象的称呼：灯→「灯」／爱音→「爱音」→ 呼び捨て，不加さん
③ 敬体度：0% → 全日语常体，一个 です・ます 都不许有
④ 高频语尾：やる／だ／ね／〜しない（平均句长 6 字）
⑤ 特殊语体：不解释、常以单词或短句收尾；情绪靠停顿不靠语气词
⑥ 中→日落地方案：中文的长句要**砍短**；不补主语；不加「〜わ」这类女性语尾
```

**未建档即开译，是最常见的失误来源。** 已建好的实测档见 `04-语尾对照表.md` 的角色索引，
自称见 `02-自称对照表.md`；名单外的（路人、客串）标「无档·按同场推断」，并在对话里说明。

## 四、逐句揣摩（**先定她想表达什么，再定日语怎么说**）

**本节是本工作的重点，也是防"机翻形态"的关口。**
中→日不是把一层意思换成另一种写法，而是替一个**具体的人**决定她此刻**要说什么**——
而五层缺项（自称／称呼／敬体／语尾／授受）只能从意图推出。

**每句按下列顺序自问，顺序不可颠倒：**

```
① 她此刻想要什么？   想让对方做出什么反应？在试探、在让步、在把话堵死，还是顺口带过？
② 这个意图在她与对方的关系里，会落成哪种说法？  绕着说／直说／把话留给对方接
③ 最后才是形式落地：自称、呼称、语尾、敬体、授受如何挂接
```

对每一句，先填这一行：

| # | 说话人 | 中文原文 | **① 她想要什么**（要什么反应／什么情绪） | ② 说法 | ③ 五问取值 | 日文 |
|---|---|---|---|---|---|---|
| 1 | 祥子 | 我不是那个意思 | 把话收回来，但不想认错；想结束这轮 | 绕着说，只否认不解释 | 自称不出现／称呼省略／敬体／`〜のよ` 收束 | そういうことではありませんの |
| 2 | 乐奈 | 做吗？ | 邀人一起做一件事；不在乎对方答什么 | 直接说，一个字 | 自称不出现／无称呼／常体／`やる？` | やる？ |
| 3 | 萤 | 对不起，我有点事 | 道歉，同时把原因压掉、不想被追问 | 道歉＋留白 | `わたし`／称呼省略／敬体／句尾收住 | ごめんなさい、ちょっと用事があって |

**第四列填不出的，说明该句尚未读进去，不要动笔。**

> **判定标准**：一句日语若换由他人说出仍成立，则该句不合格。

### 意图读不出或读出两种：**向用户确认，可多轮**

**「她想要什么」有多种合理解释时，不应代用户取舍。** 列出候选、说明各候选会把人物带向何处，
用户确认后再落笔。**确认可以多轮**——相较反复确认的成本，人物走形的代价更高。
但**交付物中不得保留「（需判）」**（见第五节）：交付物只有日文台词。

**先确认意图，再确认措辞**：

```
（对话中）这一句我读出两种，落成日语是两句不同的话：

  A 她在试探素世是否站她这边
    → そう……そよさんは、どうするつもり？（探问口气收尾，把话递过去）
  B 她只是把话说完，并未多想
    → そう。なら、これでいいわね（平的结论，把这一轮关掉）

  按这一场她们刚争执过，我倾向 A——请确认取哪一个。
```

以下问法不成立：

```
（✗）这里用 〜のよ 还是 〜わよ？      ← 意图未定，无从选择
```

### 缺项五问（③ 形式落地时按固定顺序过一遍）

中文没写、日语必须写的五类：

```
① 自称要不要出现？（中文常省主语 → 日语补不补、补哪个）
② 称呼要不要出现？（中文「你」无差别 → 日语必须选：名字／さん／ちゃん／省略）
③ 敬体度是多少？（**不能看中文有没有「您」**，看角色档与场合）
④ 语尾语气是什么？（中文「吧／呢／啊」→ 日语选一个终助词，或不加）
⑤ 授受方向有没有？（「给你／帮我／替我」→ 〜てあげる／〜てくれる／〜てもらう）
```

**第 ③ 条最容易错**：中文说「您」不一定是敬体关系（也可能是阴阳怪气），
中文说「你」也可能是敬体（日语里敬体与二人称无关）。**敬体度只看角色档 + 场合。**

### 分片：一次一幕，≤ 30 句

- **一次只做一幕**（≤ 30 句），做完自检这一幕，再进下一幕；
- 换幕时**重念一遍六行语体档**——长稿最常见的失误是敬体度在中途漂移；
- 超过 30 句的任务**必须分片**，不要一口气过完。

> 分片属于质量闸门，而非效率手段：**"整篇一次成稿"是机翻的典型形态**——
> 它没有"这一幕与上一幕并非同一回事"的概念。逐句表不必全部交付，但必须真实存在：
> 用户可随时指定任一句追问「她这句想要什么」，第四列答不出者退回第二步。

## 五、拿不准的怎么办：**在对话里问，不要写进稿子**

先分辨类型——拿不准分两种：

| 哪种 | 长什么样 | 去哪问 |
|---|---|---|
| **意图不明**（优先） | 该句她想要什么，读出两种，或根本读不出 | **第四节**——给出两种意图对应的写法，请用户确认。可多轮 |
| **说法不定** | 意图已定，但落成日语有几种都成立 | 本节的问法（见下） |

意图未定时不要在措辞上打转：**「用 `〜のよ` 还是 `〜わよ`」无从选择——
选择的依据（她想做什么）尚未确定。**

说法层的问法——列出候选、说明代价、等待用户选择：

```
（对话里）这句「……」我给了两个写法：
  A 〜のよ（说明语气，像祥子那种）
  B 〜わよ（主张语气，更硬）
  按她这一场的关系，我倾向 A——你要哪个？
```

**列出候选、说明代价、等待用户选择**，然后只把选中的那一句落进稿件。
**不要在交付物里留「（需判）」**——那是给译者看的，不是给配音稿看的。

> **确认可以多轮。** 意图层的反复确认属于正常：一句台词的读法，本就只有创作者最清楚。
> 风险不在问得多，而在未确认即代为定夺。

## 六、常用判断：什么时候可以"整套升级/降级"

| 场景 | 可以做 | 不可以做 |
|---|---|---|
| 对陌生人转正式 | 句式转敬体（です・ます）、称呼加さん | 把「あたし」换成「わたくし」（那是换人格） |
| 生气 | 语尾变短、句尾变硬、称呼改回全名／姓 | 突然转敬体（除非该角色本身敬体，如祥子） |
| 撒娇 | 拖音（〜）、重复、终助词增多 | 把常体改成敬体 |
| 台上/台下（Ave Mujica 代号） | **整套换**（自称、语尾、敬体、句长全换，见角色索引） | 只换一句里的一个词——那是最易失真的写法 |

## 七、三个中文特有的陷阱

1. **中文成语／网络语不要直译**。先用一句日语把意思说出来，再按语体调。
2. **中文的"我们"要看是包含听者还是排除听者**（`私たち`／`我々`／`うちら` 语感不同）。
3. **中文没有敬体一致的要求，日语有**；写长段时每句都要重新确认敬体度没漂。

## 八、交稿前

按 `06-自检清单.md` 过一遍，再跑一遍体检：

```bash
node tools/vtool.mjs audit 稿子.txt --src 中文原文.txt
```

时间不够时，至少跑 ① 遮名测试、② 敬体一致性、⑬ 机翻痕迹体检这三条。
